# 학교 축제 복면가왕 실시간 QR 투표

관람객은 계정 없이 같은 QR로 접속하고, 관리자는 참가자 등록·경기 생성·투표 시작·마감·재개·결과 공개를 화면에서 운영합니다. React·TypeScript·Vite·Tailwind CSS, Cloudflare Workers Static Assets·D1을 사용합니다. 관람객과 프로젝터에는 Cloudflare, Google, ChatGPT 계정이 필요하지 않습니다. **배포 담당자에게만 Cloudflare 계정이 필요합니다.**

> 현재 검증 범위: Worker 코드를 직접 호출하는 오프라인 API 테스트, 암호·입력 검증 테스트, 실제 SQLite 동시 쓰기 테스트를 실행했습니다. npm 저장소 접근 불가로 의존성 설치·TypeScript 전체 빌드·브라우저·Wrangler/D1 실환경·k6 700 VU 검증은 아직 실행하지 못했습니다. 이 프로젝트를 행사에 사용하기 전 아래 빌드 및 스테이징 절차를 반드시 마쳐야 합니다. 배포된 주소는 아직 없습니다. [검증 기록](docs/검증기록.md)을 확인하세요.

## 1. 먼저 준비할 것

- 배포용 노트북, 인터넷 연결, Cloudflare 계정
- Node.js 22.12 이상 (권장: 현재 지원 중인 Node.js 24 LTS): https://nodejs.org/
- Python 3.10 이상: 오프라인 DB/API 테스트에 사용합니다. Windows는 `python3` 명령으로 실행되는지 확인하세요.
- 행사 전 테스트용 스마트폰 최소 2대
- 프로젝트 폴더 전체 (이 README가 들어 있는 `festival-vote` 폴더)

Windows는 VS Code 터미널이나 PowerShell을, macOS는 터미널을 열고 폴더로 이동합니다. 아래 명령은 특별한 표시가 없으면 프로젝트 폴더에서 실행합니다.

```bash
cd festival-vote
node --version
npm --version
npm install
```

의존성은 호환 범위의 안정 버전을 사용하도록 선언했습니다. 이 환경에서는 npm 접속이 실패해 최신 버전 확인과 잠금 파일 생성이 불가능했습니다. 첫 `npm install` 성공 후 생성된 `package-lock.json`을 함께 보관하세요. 이후 동일한 설치는 `npm ci`로 재현할 수 있습니다. 행사 직전 무분별하게 패키지를 업데이트하지 마세요.

## 2. 내 컴퓨터에서 먼저 실행

### 2-1. 로컬 관리자 비밀번호 생성

```bash
npm run secrets:local
```

화면에 나오지 않는 비밀번호를 두 번 입력합니다. 16~128자의 긴 비밀번호를 사용하세요. 해시와 난수 비밀키가 `.dev.vars`에 저장됩니다. 비밀번호 원문을 저장하지 않습니다. 파일을 공유하거나 Git에 올리지 마세요. 파일이 이미 있으면 덮어쓰지 않습니다.

### 2-2. 테스트용 DB 생성 및 실행

```bash
npm run db:local
npm run dev
```

Wrangler가 로컬 DB를 생성하고 Vite 빌드 후 단일 서버를 실행합니다.

- 관람객: http://localhost:8787/
- 관리자: http://localhost:8787/admin
- 프로젝터: http://localhost:8787/display

`wrangler.jsonc`의 `database_id`는 로컬 개발에서는 실제 운영 ID가 필요하지 않습니다. 도구 버전이 자리표시자를 거부하면 아래 3-2에서 생성한 실제 ID를 입력한 뒤 `--local` 명령을 사용하세요. `--remote`를 붙이지 않으면 운영 DB에 적용되지 않습니다.

로컬에서 Secure 쿠키를 허용하는 최신 Chrome/Edge의 `localhost`를 사용하세요. 쿠키가 저장되지 않는 환경에서는:

```bash
npm run build
npx wrangler dev --local --port 8787 --local-protocol https
```

터미널에 나온 `https://localhost:8787`을 열고 로컬 자체 서명 인증서 안내를 처리합니다. 휴대폰 시험은 아래 HTTPS 스테이징 배포로 진행하세요. localhost QR은 다른 휴대폰에서 접속할 수 없습니다.

코드를 수정하는 개발자용으로만, 별도 터미널에서 `npm run ui`를 실행하면 Vite 개발 서버가 8787 API로 프록시합니다. 일반 운영자는 필요 없습니다.

## 3. Cloudflare에 HTTPS 사이트 배포

### 3-1. Cloudflare 로그인

https://dash.cloudflare.com/ 에서 계정을 만들고 다음을 실행합니다.

```bash
npx wrangler login
npx wrangler whoami
```

열린 브라우저에서 본인 계정을 허용합니다. 이 로그인은 배포용이며 관람객에게 요구하지 않습니다. 계정 제한·요금·학교의 행사 운영 규칙을 배포 전에 확인하세요.

### 3-2. 운영 DB 생성

```bash
npx wrangler d1 create festival-vote
```

출력의 `database_id`를 복사합니다. **직접 수정할 설정값은 `wrangler.jsonc`의 다음 한 곳입니다.**

```text
"database_id": "REPLACE_WITH_YOUR_D1_DATABASE_ID"
```

자리표시자를 본인 DB ID로 바꿉니다. 중괄호나 따옴표를 지우지 마세요. Worker 이름 `festival-vote`가 본인 계정에서 이미 사용 중이면 `name`도 원하는 영문 소문자·숫자·하이픈 이름으로 바꾸세요. DB 이름과 바인딩 `DB`는 그대로 두는 것이 쉽습니다.

```bash
npm run db:remote
```

이 명령은 **실제 D1**에 스키마를 적용합니다. 기존 표는 초기화하지 않습니다. 테이블 삭제나 마이그레이션 파일 수정으로 행사 데이터를 초기화하지 마세요.

### 3-3. Worker 최초 등록과 운영 비밀키 (최초 1회)

먼저 빌드 검사와 최초 배포로 Worker를 등록합니다. 아직 비밀키가 없어서 API는 안전하게 ‘서버 설정 필요’(503)로 응답합니다. 이 단계에서 관람객에게 QR을 배포하지 마세요.

```bash
npm run build
npx wrangler deploy
node scripts/setup-secrets.mjs --remote
```

운영 관리자 비밀번호를 두 번 입력합니다. 생성 도구는 비밀번호 원문을 올리지 않고 다음 3개를 Wrangler의 표준 입력으로 Cloudflare Secrets에 등록합니다.

- `ADMIN_PASSWORD_HASH`: 난수 소금과 PBKDF2-SHA256 100,000회 해시
- `COOKIE_SECRET`: 방문자 쿠키 서명 및 투표자 파생 해시용
- `SESSION_SECRET`: 관리자 세션·로그인 시도 식별 해시용

실제 키를 소스·브라우저 코드·명령줄 인수에 넣지 않습니다. **행사 도중 이 도구를 다시 실행하지 마세요. 방문자 키가 바뀌면 기존 브라우저 식별이 바뀌고 중복 제한이 약해집니다.** 관리자 비밀번호만 바꾸려면 [장애 대응](docs/운영매뉴얼.md)을 참고하세요.

### 3-4. 검사하고 배포

```bash
npm test
npm run build
npm run test:workerd
npx wrangler deploy --dry-run
npm run deploy
```

첫 배포에서 `workers.dev` 주소 활성화 안내가 나오면 Cloudflare 대시보드에서 활성화합니다. 최종 출력의 `https://festival-vote.본인계정.workers.dev` 형태 주소가 실제 주소입니다. 예시 주소를 그대로 QR에 쓰지 마세요. Cloudflare 대시보드 → Workers & Pages → 해당 Worker에서도 확인할 수 있습니다.

사이트와 API는 같은 도메인에서 동작합니다. 별도 프런트엔드 호스팅이나 CORS 설정이 필요 없습니다. HTTPS 주소로 관리자에 로그인하고 스마트폰 두 대로 검증하세요.

배포 명령은 로컬 DB나 로컬 `.dev.vars`를 운영으로 복사하지 않습니다. 운영 DB와 운영 Secrets 설정은 각각 필요합니다.

## 4. 운영 방법 (코드 수정 불필요)

1. 실제 사이트 주소 뒤에 `/admin`을 붙여 로그인합니다.
2. **참가자 관리 → 참가자 등록**으로 16명을 등록합니다. 실제 이름·메모는 관리자만, 복면 이름·선택 이미지 URL은 관람객에게 표시됩니다.
3. 이미지가 없으면 기본 복면 그래픽을 사용합니다. 이미지는 공개 HTTPS 주소만 가능하며 직접 파일 업로드는 제공하지 않습니다. 제3자 이미지 호스트는 관람객의 이미지 요청 정보를 받을 수 있으므로 학교가 관리하는 이미지 호스트를 권장합니다.
4. **QR 생성·인쇄**를 누릅니다. 인쇄 또는 PDF로 저장합니다. 주소가 배포된 HTTPS 루트 주소인지 스마트폰으로 확인합니다.
5. **프로젝터 화면**을 새 창으로 열어 빔프로젝터에 배치합니다. 전체 화면 버튼 또는 브라우저 F11을 사용합니다.
6. **새 경기 만들기**에서 라운드·경기명·서로 다른 활성 참가자 2명을 선택합니다. 경기 생성과 현재 화면 선택이 함께 처리되고 READY가 됩니다.
7. **투표 시작**을 누릅니다. 관람객 화면에는 대체로 10~14초 이내 반영됩니다. 관람객이 새로고침을 누르면 즉시 갱신합니다.
8. 관리자만 실시간 득표를 확인합니다. **투표 마감**을 누르면 새 표가 차단됩니다.
9. CLOSED에서는 **투표 재개** 또는 **결과 공개**를 선택할 수 있습니다. 재개해도 기존 표는 유지됩니다.
10. 사회자의 신호에 맞춰 **결과 공개**를 누릅니다. 프로젝터는 대체로 3초, 관람객은 대체로 12초 이내 반영됩니다. 네트워크 지연 시 더 늦을 수 있습니다. 공개한 경기는 되돌릴 수 없습니다.
11. 다음 경기를 새로 만들고 C·D 등을 선택합니다. 기존 QR 그대로 참여하며 경기별로 다시 1표를 낼 수 있습니다. 우승자 자동 배정이나 고정 대진표는 없습니다.
12. 결승 종료 후 **경기 기록 → 전체 결과 CSV**를 내려받습니다. 경기별 CSV 및 참가자 CSV도 제공합니다. 한국어 Excel용 BOM 및 수식 삽입 방어가 적용됩니다.

현재 경기 변경은 OPEN 상태에서는 거부됩니다. 마감 후 다음 경기를 만들 수 있지만, 발표할 경기는 먼저 공개한 뒤 다음 경기를 만드는 것을 권장합니다. **경기 기록을 읽는 것은 현재 화면에 영향을 주지 않습니다.** ‘현재 화면에 표시’를 누르면 명시적으로 그 경기로 전환합니다. 과거 공개 경기의 결과도 다시 표시할 수 있으나 수정·재개는 불가능합니다.

## 5. 투표의 정확성과 한계

- 서버가 암호학적 난수로 방문자를 발급하고 HMAC 서명한 `Secure·HttpOnly·SameSite=Strict` 쿠키를 사용합니다. 유효기간은 7일입니다.
- DB에는 원본 방문자 ID 대신 도메인을 구분한 HMAC 파생값만 저장합니다. 회원·이름·전화번호·관람객 IP를 투표 테이블에 저장하지 않습니다.
- `UNIQUE(match_id,voter_hash)`와 전역 요청 ID 고유 제약이 최종 중복 방지 기준입니다. ‘조회 후 삽입’만으로 판단하지 않습니다.
- 현재 경기·OPEN 상태·두 참가자 중 선택 여부를 `INSERT ... SELECT` 하나로 확인하고 저장합니다. DB 트리거도 검증합니다. SQLite/D1의 쓰기 순서상 마감 이후 새로운 표가 삽입되지 않습니다.
- 투표 전 방문자 쿠키 발급을 먼저 확인합니다. 쿠키가 없는 첫 투표는 428로 거부하여 첫 응답 유실로 방문자 식별이 사라지는 문제를 줄입니다.
- 제출 직전 요청 ID와 선택을 로컬 저장소에 보관합니다. 새로고침·응답 유실 후에는 같은 ID를 재사용하며 내 표 조회로 확인합니다. 마감 뒤에도 이미 저장된 표의 동일 선택 재시도는 성공을 반환합니다. 다른 참가자로 변경은 거부합니다.
- 브라우저 쿠키 삭제, 시크릿 창, 다른 브라우저/기기 사용은 같은 사람임을 완벽히 식별할 수 없습니다. **절대적인 1인 1표를 보장하지 않습니다.** 쿠키·저장소를 끄면 투표가 제한됩니다.
- 클라이언트 시간이 아닌 DB 시각을 기록합니다. 상태 변경은 경기 버전, 현재 경기 지정은 행사 버전을 검사하며 충돌은 409로 거부합니다.
- 공개 API는 명시적인 허용 필드만 응답합니다. CLOSED까지 득표·비율·승자·실제 이름·메모를 전달하지 않습니다. 집계는 서버에서만 합니다. 공개한 결과는 다시 숨기지 않습니다.
- 관리자 세션은 8시간, 로그인 제한은 IP를 비밀키로 해시한 값 기준 15분 15회입니다. **IP 제한은 관리자 로그인에만 사용**하며 공용 Wi-Fi의 관람객을 하나로 묶지 않습니다. 관람객 제출 제한은 익명 방문자 기준 분당 30회입니다.
- 관리자 쓰기는 동일 출처 검사·JSON 요청·세션별 CSRF 토큰을 요구합니다. 공개 투표 쓰기도 동일 출처 검사를 합니다. SQL은 준비된 문장, 화면은 React 텍스트 렌더링을 사용합니다. API와 화면에 보안 헤더·no-store를 적용합니다.
- 비정상 쿠키는 거부하고 지웁니다. 재접속해 쿠키를 새로 받게 되면 재식별의 한계가 발생합니다. Cloudflare 자체 엣지 보안/접속 로그는 플랫폼 정책을 따릅니다.

## 6. 요청량·비용·700명 시험

관람객 상태 조회는 평균 12초에 한 번, ±15% 무작위 지연입니다. 숨겨진 탭은 조회를 멈추고 약 30초마다 활성 여부를 확인합니다. 탭 복귀·온라인 복귀 시 즉시 동기화합니다. 관리자·프로젝터는 평균 3초입니다. 타이머 중첩을 막고 요청은 12초 후 시간 제한을 적용합니다.

700명이 계속 화면을 켠 2시간을 가정하면:

```text
관람객 상태: 700 × 7,200 / 12 = 약 420,000회
관리자 1 + 프로젝터 1: 2 × 7,200 / 3 = 약 4,800회
16경기 × 700표: 약 11,200회 제출 + 약 11,200회 내 표 조회
첫 로딩 정적 파일·기록·재시도: 추가
합계: 대략 45만 요청 이상 / 2시간
```

D1은 상태 요청당 현재 상태/경기를 읽고, 투표당 속도 제한 쓰기·투표 쓰기·확인 읽기 등이 추가됩니다. 공개 후에는 집계 조회도 있습니다. 집계 인덱스는 경기별로 사용하지만 반환 행 수와 읽은 행 수는 같지 않습니다. 무료 플랜의 Workers 일일 요청 한도가 100,000회인 조건에서는 **상시 관람객만 약 28.6분이면 초과**할 수 있습니다. 행사에는 유료 Workers 플랜을 권장하며 D1 읽기·쓰기·CPU 한도와 비용은 아래 공식 페이지에서 계정의 현재 조건을 확인하세요. 이 환경에서 2026년 현재 요금을 조회하지 못했으므로 금액이나 현재 한도를 보증하지 않습니다.

- https://developers.cloudflare.com/workers/platform/pricing/
- https://developers.cloudflare.com/d1/platform/pricing/
- https://developers.cloudflare.com/d1/platform/limits/

정적 자산은 요청 과금 정책이 다를 수 있지만 이 구성은 보안 헤더를 위해 Worker를 먼저 실행하므로 동적 호출량을 보수적으로 계산하세요. 매초 700명 폴링은 하지 않습니다. D1 포화·일일 한도·학교 Wi-Fi 대역폭에 따라 실측 용량이 달라집니다. 700명 지원이 검증되었다고 주장하지 않습니다.

[700명 부하 시험 설명](load/README.md)의 A~F를 **별도 스테이징**에서 실행하세요. 실서비스에 부하를 가하지 마세요. SQLite 테스트의 700표 결과는 Worker와 실제 무선망의 성능 검증을 대체하지 않습니다.

## 7. 행사 전 필수 점검

- [ ] `npm install`, `npm test`, `npm run build`, `wrangler deploy --dry-run` 통과
- [ ] 스테이징에서 k6 A~F 통과, 최종 합계 일치
- [ ] 실기기 2대에서 쿠키·동일 경기 중복 방지·다음 경기 재투표 확인
- [ ] 한 표를 제출하고 응답 확인 전에 비행기 모드 → 복구 → 내 표 확인/같은 요청 재시도
- [ ] OPEN에서 표 제출 → 마감 → 새 기기 표 거부 → 기존 표 재시도 성공
- [ ] CLOSED에서 공개 API·개발자 도구 응답에 득표·승자 없음 확인
- [ ] 재개 후 기존 표 유지, 공개 후 재개 불가 확인
- [ ] 참가자 이름 수정 후 과거 경기 이름 유지 확인
- [ ] 관리자를 로그아웃하고 집계/CSV 접근이 401인지 확인
- [ ] 동일 QR로 1경기·2경기·결승 참여 확인
- [ ] 프로젝터 해상도·전체 화면·동점 연출 확인
- [ ] 전체 경기/참가자 CSV를 Excel로 확인
- [ ] 인쇄된 실제 QR 스캔 확인, 장기 사용용 주소 보존
- [ ] Cloudflare 결제·한도·D1 백업 확인
- [ ] 리허설 DB와 행사 DB 분리, 운영자 1명에게 상태 조작 집중
- [ ] 예비 인터넷·충전기·핫스팟·종이 투표 등 학교에서 정한 대안 준비

장애 대응과 현장 진행 순서는 [운영 매뉴얼](docs/운영매뉴얼.md), API 형식과 오류는 [API 문서](docs/API.md)를 참고하세요.

## 8. 프로젝트 구조와 단계

```text
src/                  React 관람객·관리자·프로젝터 UI, 통신·스타일
worker/               REST API, 인증·쿠키·입력·CSV 보안
migrations/           D1 SQL 마이그레이션과 원자적 제약·트리거
scripts/              비밀키·관리자 비밀번호 초기 설정
tests/                실제 Worker 호출 테스트, SQLite 병렬 쓰기 검증
load/                 k6 700 VU A~F 시나리오
docs/                 API·운영·검증 기록
wrangler.jsonc        Workers·Static Assets·D1 설정
```

1. 프로젝트 구성: Vite·React·Tailwind·TypeScript·Wrangler 설정 작성
2. DB 및 API: 스키마·마이그레이션·공개/관리자 REST 작성
3. 투표 처리: 쿠키 서명·원자적 삽입·고유 제약·재시도 작성
4. 관리자 시스템: PBKDF2·세션·CSRF·참가자/경기/집계/CSV 작성
5. UI: 모바일 투표·대형 화면 결과·QR·운영 화면 작성
6. 검증: 보안·API·SQLite 경합 테스트 실행, k6 구성 제공. 빌드/실환경 검증은 아직 남음
7. 배포 준비: 초보자 설치·배포·운영·장애 안내 작성. 실제 계정 등록/배포는 담당자가 수행

구성과 한도를 현장에서 다시 확인할 공식 문서:

- https://developers.cloudflare.com/workers/static-assets/routing/advanced/worker-script/
- https://developers.cloudflare.com/d1/worker-api/prepared-statements/
- https://developers.cloudflare.com/d1/worker-api/d1-database/#batch
- https://developers.cloudflare.com/d1/sql-api/foreign-keys/
- https://developers.cloudflare.com/workers/configuration/secrets/
- https://developers.cloudflare.com/workers/wrangler/commands/
