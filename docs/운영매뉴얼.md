# 현장 운영 매뉴얼

## 전날 리허설

1. 별도 스테이징 DB에서 설치·빌드·기능 시험과 k6 A~F를 진행합니다.
2. 운영 사이트는 HTTPS 단일 주소로 확정합니다. 행사 중 Worker 이름·도메인·방문자 비밀키를 바꾸지 않습니다.
3. 관리자 비밀번호를 담당자만 아는 안전한 곳에 보관합니다. 프로젝터 PC에는 관람객용 `/display`만 띄워도 됩니다.
4. 참가자 16명과 복면 이름을 확인합니다. 실제 이름과 메모는 공개 화면에 나오지 않습니다. 메모에 민감한 개인정보를 적지 않습니다.
5. QR 인쇄물을 휴대폰 카메라로 스캔합니다. 학교 Wi-Fi와 이동통신 각각 접속합니다. 카메라에서 새 창을 반복해 열기보다 기존 투표 탭을 유지하도록 안내합니다.
6. 참가자 이미지는 저용량으로 준비하고 HTTPS 주소가 계속 유효한지 확인합니다. 없으면 기본 복면 그래픽으로 운영할 수 있습니다.
7. 16:9 프로젝터 전체 화면에서 결과·동점·0표 결과를 확인합니다. 애니메이션은 접근성의 동작 줄이기 설정을 따릅니다.
8. 경기 제어는 주 운영자 한 명이 맡습니다. 여러 운영자가 동시에 조작하면 버전 충돌 안내가 나오므로 최신 상태를 확인합니다.

## 축제 시작 전

- 관리자 로그인은 8시간 동안 유지됩니다. 시작 직전에 다시 로그인하면 세션 만료 가능성을 줄일 수 있습니다.
- 참가자 목록·경기명·QR 주소·프로젝터 창을 확인합니다.
- 테스트 투표를 실제 경기 기록에 섞지 않습니다. 리허설은 별도 DB에서 합니다. 기존 기록 삭제 기능은 제공하지 않습니다.
- 실수로 만든 경기라도 DB를 직접 삭제하지 않습니다. 새 경기를 만들고 해당 기록은 시험 기록임을 경기명으로 구별합니다. 이름 변경 API는 제공하지 않으므로 경기 생성 전에 확인하세요.

## 경기마다

1. 새 경기 → 라운드·이름·두 참가자 확인 → READY 화면 확인
2. 사회자 신호 → 투표 시작 → 프로젝터의 ‘투표 진행 중’ 확인
3. 관람객이 선택을 확인하고 큰 투표 버튼을 누르도록 안내
4. 관리자만 득표수 확인 → 충분한 응답 시간 확보 → 투표 마감
5. 마감 시점 전에 DB에 반영된 표까지 유효합니다. 네트워크상 먼저 보냈어도 DB에서 마감 뒤에 처리되면 거부됩니다.
6. CLOSED에서 득표를 확인하고, 필요 시 재개 (기존 표 유지)
7. 사회자 신호 → 결과 공개. **공개는 되돌릴 수 없습니다.**
8. 다음 경기 생성. 같은 QR에서 자동으로 새 경기가 표시되는지 확인

## 장애 대응

| 증상 | 우선 행동 | 하지 말아야 할 일 |
|---|---|---|
| 관람객 ‘응답을 받지 못했음’ | 온라인 복구 → 내 투표 상태 확인 → 같은 요청으로 재시도 | 새 기기/시크릿 창으로 중복 투표 유도 |
| ‘방문자 쿠키’ 오류 | 새로고침 후 상태 확인. 쿠키 차단 해제 | 쿠키 삭제를 보편적인 해결법으로 안내 |
| 화면이 이전 경기 | 새로고침, 탭 다시 활성화, 네트워크 확인 | QR을 새 경기마다 다시 만들기 |
| 관리자 상태 충돌 409 | 최신 상태 확인, 다른 운영자와 조작 조율 | 버튼 반복 누르기 |
| 서버 503/느림 | 투표 상태 확인, Cloudflare 상태·대시보드 요청/DB 한도 확인 | 성공 여부 불명확한 표를 실패로 단정 |
| 학교 Wi-Fi 장애 | 사회자 안내, 투표 마감 유예/재개, 허용된 이동통신 활용 | 임의로 표를 더하거나 CSV로 표 수정 |
| 관리자 로그인 제한 | 비밀번호 확인 후 최대 15분 창이 바뀔 때까지 기다림 | 계정 공유·대량 로그인 재시도 |
| 세션 만료 | 관리자 다시 로그인, 최신 경기/집계 확인 | DB 초기화 |
| 프로젝터 화면 멈춤 | 연결 확인·수동 갱신·브라우저 전체 화면 재설정 | 관리자 대시보드를 대형 스크린에 노출 |
| 요금/일일 한도 초과 | Cloudflare 요금제/한도 확인, 학교가 승인한 대안 사용 | 오류를 무시하고 결과 확정 |

웹페이지를 새로고침하거나 Worker 코드를 재배포해도 D1 기록은 유지됩니다. `.wrangler` 삭제는 로컬 테스트 DB에 영향을 줍니다. 운영 데이터가 있는 D1은 삭제·재생성하지 않습니다.

## 비밀번호 변경/분실

방문자 식별키를 보존하기 위해 `setup-secrets.mjs --remote` 전체 초기화를 다시 실행하지 않습니다. 관리자 비밀번호만 바꾸려면 다음 전용 명령을 사용합니다.

```bash
node scripts/change-password.mjs
```

이 명령은 ADMIN_PASSWORD_HASH만 변경하고 방문자/세션 서명키는 유지합니다. 기존 관리자 세션은 DB에서 별도로 만료시키세요. 정상 운영 중에는 먼저 UI에서 로그아웃합니다. 분실·탈취 상황에서 전체 관리자 세션을 무효화하려면 본인 운영 DB임을 확인하고:

```bash
npx wrangler d1 execute festival-vote --remote --command "DELETE FROM admin_sessions;"
```

비밀번호 변경만으로 기존 세션이 자동 만료되는 구조는 아닙니다. 방문자 키가 노출되면 행사 투표의 신뢰성 판단을 학교 담당자와 진행하고, 진행 중 키를 임의 교체하지 마세요.

## 백업과 종료

운영 전·운영 후에 별도 안전한 위치로 DB를 내보냅니다.

```bash
npx wrangler d1 export festival-vote --remote --output=festival-backup.sql
```

백업에는 투표자 파생 해시와 관리자 세션 등이 포함될 수 있습니다. 공개 자료로 배포하지 마세요. 관리자 CSV는 내부 비밀값을 제외하므로 공유용으로 검토하기 쉽습니다. 참가자 CSV의 실제 이름·관리 메모도 공개 전에 확인하세요.

행사 후 전체 결과 CSV와 참가자 CSV를 받아 학교의 보관 규칙에 따라 저장합니다. 관리자 로그아웃을 확인합니다. 공개 사이트를 닫을 경우 학교 담당자가 Cloudflare 대시보드에서 Worker의 공개 라우트를 비활성화할 수 있습니다. 기록을 보존해야 하므로 D1은 바로 삭제하지 않습니다.

## 플랜과 용량

700명은 서버뿐 아니라 강당의 무선 AP, 인터넷 회선, 각 휴대폰의 절전 상태 영향을 받습니다. 실제 스테이징 부하와 현장 기기 리허설을 모두 진행하세요. 표 정확성을 위해 상태 갱신을 더 빠르게 만들려고 관람객 폴링을 매초로 줄이지 마세요. DB와 Workers 한도는 배포 당일 계정에서 확인합니다.
